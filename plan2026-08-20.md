## Design Principles

1. **Voice-native, not voice-bolted-on.** Every action has a voice path.
2. **Confirm before destroy.** Delete, send, shutdown — always confirm.
3. **Narrate, don't silence.** "Fetching that page..." — user should never wonder.
4. **Summarize, don't dump.** Long content gets condensed.
5. **Remember, don't ask again.** Learned credentials, preferences, patterns.
6. **Queue, don't interrupt.** Focus-aware notification delivery.
7. **Barge-in always works.** User speaks → Artume stops and listens.
8. **Mode-aware context.** "Read this" means different things in different modes.

## Success Criteria

The project is complete when a blind user can:

1. Wake Artume with "Hey Artume"
2. Check email, browse web, manage files — all by voice
3. Read and edit code in the Audio-First IDE with spatial audio
4. Debug with breakpoints, step-through, variable inspection
5. Use Git, run tests, manage terminal — all by voice
6. Navigate with LSP (go to definition, find references, rename)
7. Manage bookmarks, search email, sort files — all by voice
8. Never need to see a screen, touch a keyboard, or use a mouse
